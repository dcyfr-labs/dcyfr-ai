# Documentation Audit, November 2026

Audit of every file under `docs/` and the root `README.md` against the source at the commit this branch was cut from. Each claim checked was an exported symbol, an import path against `package.json` `exports`, a CLI command or flag against `bin/`, an environment variable against the code that reads it, an npm script, or a relative link.

## Method

- `npm ci`, `npm run build`, then `npm run check:parity` (version, exports, env, config, capabilities).
- A script compared every `import ... from '@dcyfr/ai...'` in the docs with the built package exports and the symbols each entry point exports.
- The doc-judge report ran over the 10 pages it covers (the capability bootstrap reference and the generated API pages). It flagged none and logged 3 judge faults.
- The doc-living MCP could not be used: it failed to resolve its source mirror in this environment. Source was read directly instead.

## Counts

- keep: 30
- fix: 9
- fix (open): 9
- archive: 1

`fix` means the mechanical corrections are applied in this change. `fix (open)` means some corrections are applied or none are possible mechanically, and a larger rewrite remains.

## Moved

## TUI.md decision

TUI code does exist: `bin/tui.js` and `bin/tui/` ship in the package, with a `dcyfr-ai-tui` binary. It is not under `packages/ai`. Because code exists, `docs/TUI.md` was kept with an outdated notice rather than archived. If the owners prefer to archive it, `TUI_IMPLEMENTATION.md` already covers the current implementation.

## Other problems found, not fixed here

- `bin/cli.js` help text labels `tui:dashboard` and `tui:wizard` as OpenTUI.
- `examples/tui/README.md` describes the examples as OpenTUI based.
- `package.json` maps `@dcyfr/ai/mcp` to `packages/ai/mcp`, while `MCPToolBridge` lives in `packages/ai/src/mcp`, so the README example cannot work as written.
- `docs/api/` pages cover nine entry points, and `@dcyfr/ai/delegation` style subpaths used in several guides are not package exports.
